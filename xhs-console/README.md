# xhs-console · 小红书人工值守控制台（通用核心框架）

> 一套帮小红书账号运营者**把「散落的消息」收敛成一个浏览器看板**的半自动中控：
> 真人打开一眼看全——**谁来了 / 怎么回 / 回了没**。机器只拟稿、分级、归集、记回流，
> **发消息、加微、约见等关键动作永远由真人执行**。

- 定位：**通用核心框架**。采集、分级拟稿、回复策略、主动获客、控制台主链路全部开源；
  你的**真实业务配置**（人群、话术、账号、价格、客户名）**不内置**，按 README 用示例改写即可。
- 默认端口 `8090`，仅依赖 Python 标准库 + PyYAML，本地跑，**不把数据上传任何服务器**。

---

## 一、这是什么

很多小红书账号运营者的日常是：私信散落、评论区没人盯、主动去别人笔记下留言又怕踩雷、
回复靠手感、超时漏单。这套系统把「人工值守」的每一步**半自动化**：

| 环节 | 机器做的 | 人做的 |
|---|---|---|
| 采集 | 自动拉私信 / 评论区 / 主动搜索笔记 | 不定期点刷新 |
| 分级 | 按意图库打 P0-P3 + 判别真假商机 | 复核 |
| 拟稿 | 按对话阶段 + 来源 + 人群生成回复草稿 | 润色、改用、**真人发** |
| 主动获客 | 按人群库去目标笔记下留言（可关） | 审核留言、承接私信 |
| 回执 | 每条的「已回 / 对方反应 / 真商机」落回流表 | 逐条勾选保存 |

> 核心精神：**机器可以替你想，但永远不替你说。** 保号安全线压在真人「发」这一下。

## 二、目录结构

```
xhs-console/
└── interceptor/
    ├── collector/            # 采集层（只读，拉消息）
    │   ├── collect_inbox.py        # 私信采集
    │   ├── collect_comments.py     # 评论区采集
    │   ├── auto_reply.py           # 白名单自动回复（开关控制）
    │   └── proactive_engage.py     # 主动获客：去目标笔记下留言
    ├── classify/             # 分级拟稿层（读采集件，产出分级+首稿）
    │   ├── classify_draft.py       # 意图分级 P0-P3 + 首拟稿
    │   ├── reply_diagnose.py       # 场景诊断（5 信号）
    │   ├── reply_strategy.py       # 策略命中器（阶段×来源×人群）
    │   ├── reply_compose.py        # LLM 组合润色（可降级为规则兜底）
    │   ├── reply_self_learn.py     # 自学习闭环（样本→打分→回灌叠加层）
    │   ├── proactive_plan.py       # 主动获客：笔记→留言规划
    │   └── *.yaml                  # 意图库 / 人群库 / 策略库 / 叠加层（示例）
    └── console/              # 控制台层（唯一可写回流表）
        ├── server.py               # 本地 http 服务 /api/state /api/draft /api/followup
        ├── dashboard.html          # 看板前端（私信 / 评论区 / 主动获客 / 内容排期）
        ├── content_workbench.html  # 内容工作台（iframe 隔离，localStorage）
        ├── lanes.yaml              # 赛道×账号 调度（示例）
        └── strategy.yaml           # 承接策略引擎（示例）
```

## 三、快速上手

### 环境
- Python 3.10+（已测 3.13）
- 依赖：`pip install pyyaml`（采集/主动获客另需 `uiautomator2`，见下）

### 启动控制台
```bash
cd interceptor
python console/server.py                # 默认 http://127.0.0.1:8090
python console/server.py --port 9000    # 换端口
```

### 三张表（`interceptor/out/`，首启自动建）
| 文件 | 角色 |
|---|---|
| `leads_raw.csv` | 采集原文（collect 追加写） |
| `leads_classified.csv` | 分级 + 拟稿（classify 重建） |
| `leads_comments.csv` | 评论原样（collect 追加写） |
| `leads_followup.csv` | **回流表（唯一可写）**，看板「保存回流」写入 |

### 采集到真机（可选，主动获客/评论需真机）
```bash
# 需先做小红书中控的 uiautomator2 真机对接（adb devices 拿到序列号）
export XHS_DEVICE=<你的设备序列号>          # 或写进 console/lanes.yaml
python collector/collect_inbox.py
python collector/collect_comments.py
python collector/proactive_engage.py --kw "你的搜索词"
```

## 四、配置改写指引（把你自己的业务填进去）

示例配置已含结构+1-2条示例记录，**按你的业务覆盖即可**：

| 文件 | 你要填什么 |
|---|---|
| `console/lanes.yaml` | 你的赛道（人群视角），每台账号（设备序列号）→ 赛道 |
| `console/strategy.yaml` | 承接策略：哪些意图机器自动回 / 人工回 / 不回 |
| `classify/intent_map.yaml` | 你的意图分级 P0-P3 + 关键词 + 首稿 |
| `classify/proactive_targets.yaml` | 你的目标人群库 + 留言角度 |
| `classify/reply_strategy.yaml` | 各场景的真人话术组（骨架 + 好句） |

> 所有真实业务词（账号名、设备号、价格、客户名）**默认都是示例占位**。
> 你的 `.env` 存 LLM key，**不放仓库**（见 .gitignore）。

## 五、合规与风险边界（重要，请务必读）

本工具暴露在**公开的小红书平台**上，合规是头等风险。项目内置了一套「红线词库 + 频道分流」
机制，但它**不能替你判断平台规则演进**。上线前请自查以下几点：

1. **公开区（评论区/笔记）最严**：只种草、提问，**绝不导流、卖课、留价、留联系方式**。
   平台对「私信我 / 加我 / 看主页领 / 扣数字领」是优先监控 + 加重处罚的。
2. **私信可报课程价**（你已授权明示），但**禁微信/手机号/扫码/谐音变体**，引导加微属违规。
3. **AI 内容**：AI 生成/辅助须勾选「AI 辅助创作」，纯 AI 内容需人工改 ≥30% 否则限流。
4. **频控**：评论/私信有每日上限与间隔，代码内置默认值（见 `proactive_targets.yaml` global），
   **请按你所在平台最新规则与本号健康度调整**，别用默认裸奔。
5. **风险自担**：本仓库提供的是**技术框架**，不构成任何运营合规建议；最终发布/发送/加微
   永远由**真人**执行。因使用本工具产生的平台处罚责任，由使用者承担。

> 关于**第三方平台/软件名**：正文/封面/标签出现非小红书第三方名称（即使只提到不点链接）
> 也可能被判「展示其他平台信息 / 引导前往其他平台」。公开内容里**一律泛称化**（"AI 工具"）。

## 六、多用户 / 多设备

这套模型是**「账号驱动」**：赛道跟着账号走，一台手机一个定位。

- `console/lanes.yaml` 的 `accounts` 用**设备序列号**做键，每台映射一个 `nick`（昵称）+ `lane`（赛道）。
- 前端顶栏**切账号** = 自动加载该账号的赛道策略（人群 + 话术视角都跟着切）。
- 采集/回复时的 `device` 值：优先 `--device` → 环境变量 `XHS_DEVICE` → `lanes.yaml` 唯一序列号。
- 多账号并发 = 多台真机（uiautomator2 按序列号区分），控制台同一实例聚合 `out/` 下多 device 数据。

## 七、升级方向（建议路线）

当前是「半自动 + 真人在环」。可按以下顺序演进（**每次只小步加，保号优先**）：

1. **多用户 SaaS 化**：把 `out/*.csv` + `lanes.yaml` 收敛到按用户/账号分区的目录，
   控制台加登录 + 数据隔离；本地服务改可多实例（每个用户一个端口 + 独立 `out/`）。
2. **自动人设强化**：把回复策略库交给自学习闭环持续长肉（`reply_self_learn.py` 已就位），
   用真实评论反哺话术，越用越像真人。
3. **数据漏斗**：每篇来源笔记的转化漏斗（引流→回复→真商机得分），指导选题回顾。
4. **风控加固**：把「红线词库」持续对齐最新《社区规范》，加敏感操作二次确认。
5. **合规审计**：发布前过一遍独立审计（机器审 + 人工审），宁可错杀不放水。

## 八、技术约定

- 零硬编码密钥：LLM key 走环境变量 / `.env`（`XHS_ENV_FILE` 可指定路径），仓库外。
- 下发消息永远真人在环；机器只拟稿、分级、归集、记回流。
- 控制台读取 `out/` 三张 csv，只写 `leads_followup.csv`；刷新即看新数据，不用重启。
- 端口默认 8090；`--nobrowser` 可在无浏览器环境启动。
