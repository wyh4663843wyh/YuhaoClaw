005｜客户需求→方案快速转化模板

TaskContract 四要素对齐客户方案

一句话价值

把 Task Contract 七要素套进「客户需求→方案输出」场景，让 AI 一次给出接近终稿的方案框架，减少反复修改。

解决的问题

接到客户需求后，方案方向容易跑偏；给客户的版本来回改，核心卖点越改越乱，效率低。

实现原理

Task Contract 的「目标 / 成功标准 / 失败条件 / 边界条件」四要素，正好对应方案撰写的「客户要什么 / 怎样算合格 / 绝对不能出现 / 格式和边界」四个硬约束。

准备条件

  • 客户原始需求（邮件 / 微信 / 会议纪要）
  • 明确方案类型（活动策划 / 文旅方案 / 培训大纲 / 营销策略）
  • 确定交付格式（PPT / Word / 在线文档）

操作步骤

第一步：提炼「目标」

用一句话写清：客户是谁、要解决什么问题、交付物是什么。

第二步：写「成功标准」

列出方案必须包含的模块，例如：

  • 背景与痛点分析
  • 具体执行步骤
  • 时间节点与分工
  • 预算区间
  • 预期效果

第三步：写「失败条件」

列出客户不能接受的内容，例如：

  • 没有具体时间节点
  • 预算超出客户预期区间
  • 出现未经确认的合作方名称
  • 格式不符合客户要求

第四步：写「边界条件」

补充方案边界，例如：

  • 不超过 [X] 页
  • 必须包含 [Y] 个案例
  • 不要出现 [Z] 类内容
  • 语气 [正式 / 轻松 / 紧迫]

第五步：写「探索方向」和「审查机制」

告诉 AI 可以先给 2~3 个版本方向；自己过三问：客户能看懂吗？能直接执行吗？有没有漏掉关键约束？

最终达成

一次 prompt 输出的方案框架，通过 Task Contract 四要素对齐后，内容更贴合客户需求，返工次数明显减少。
